# 预览桩：界面开发的"真页面 + 假宿主半"套路

> **2026-10-13 定稿，用户认可为范例**（原话：「这次你做的先用假数据做预览的做法很好，可以当作范例使用」）。
> 这里写的是一套**可复刻的开发回路**，不是某个脚本的说明书 —— 下次遇到的界面只要满足 §1 的判据，
> 就照这份搭。
>
> 本轮的实例是管理面板预览桩，脚本在工作文件夹（仓库外面那一层 `project\zotero-kb\`）的
> `tools\admin-preview\`：`render_admin_preview.py`、`render_scroll_preview.py`、`admin-preview.html`、
> `preview-data\*.json` + `preview-data.json`。

## 1. 什么场景该用它（判据）

**当界面跑在"别人的宿主里"、而反复启停那个宿主代价很高时，用"真页面 + 假宿主半"把宿主从回路里摘出去。**

判据（满足任意一条就该搭）：

- 页面不是独立网页，而是在**宿主容器**里跑：Zotero 内嵌 `<browser>`（`resource://` 页面）、
  DSH 客户端插件面板、Electron/WebView2 壳…… 页面与宿主之间靠**进程内消息/注入 API** 通信。
- 验证一次要付**高代价**：启动宿主慢、要**侧载/重启**、会**打扰用户**（抢占焦点、动真数据、
  真跑模型或子进程）。
- 改的是**纯表现层**：CSS、折行、密度、间距、按钮态 —— 这些**只能人眼看**，靠读代码或跑单测都看不出。

反面判据：如果那个界面本身能独立打开、或启停宿主一秒内完成，就别搭 —— 直接开宿主更省事。

## 2. 怎么搭（四步）

1. **外层页面冒充宿主半**：一个 `admin-preview.html`，里面 `<iframe src="__ADMIN_HTML__">`
   加载**真的**页面文件（`file:///…/content/admin.html`，**不是复制一份**——复制出来的那份一改就漂）。
2. **假宿主半只做转发**：监听 `message`，收到页面发的请求（本项目是 `{__kba:1,seq,op,args}`）后
   **按请求路径**查假数据、回同一形状的响应；没有的路径就明确回"预览桩没有 &lt;path&gt;"（别静默）。
3. **假数据按页/按主题拆成多个 JSON**，渲染时**合并**（本项目：`preview-data\<页名>.json` 一人一个文件
   + 根目录 `preview-data.json` 放公共基础数据）。这样**多人/多 agent 并行改不同页面时不用抢同一个文件**。
4. **驱动脚本**用无头浏览器加载这个外层页面：截图（人眼验收）或 `--dump-dom`（机器验收）。

## 3. 两种验收，缺一不可

| | 做什么 | 抓什么 |
|---|---|---|
| **人眼** | 无头浏览器截图 + 逐张 `read_image` 看 | 样式/密度/折行/对齐/颜色 —— 只能看，断言写不出来 |
| **机器** | 把断言写进页面（或临时驱动脚本），用 `--dump-dom` 取回结果 | 行为（"切页不重复取数""按钮 0 条时禁用""某元素有没有出现"）—— **比截图可靠得多** |

- **机器验收的写法**：在外层页面里定时把检查结果写进一个 `<pre id="diag">`，驱动脚本用
  `edge --headless --allow-file-access-from-files --virtual-time-budget=3000 --dump-dom <url>`
  取回整页 DOM，再截取那段文本。本项目的 `admin-preview.html` 自检的就是
  `iframe 里 KBAdmin.PAGES 的 id 列表 / #nav 按钮数 / #view 子元素数`
  —— 同一份 source of truth，一眼看出"页面脚本注册上没有、有没有报错"。
- **本轮靠它抓到的真 bug**（都已修，注释留在代码里）：
  - **`ctx.el` 是对象不是函数** → 整页渲染失败，外层只显示一行红字，看着像"这页没做"
    （`content\admin.js::show` 的 `ctx.el` 摊平，注释写着"2026-10-13 预览回路抓到"）。
  - **切页重复取数** → 反复点当前页/切回切出会重复发起渲染，日志里一串重复的"开始读…"
    （`content\admin.js::pageState` 的 `promise` 去重，注释里记了用户两次反馈）。

## 4. 四个坑（都实测过）

1. **无头截图高度别超 ~1400**：超了**不出图**（本项目实测的经验上限）。
2. **临时运行文件每次换文件名**：无头浏览器会缓存 `file://` 的同一 URL，改了页面再渲染拿到的是
   **上一张图**（两次出图字节数完全相同，排查了半天）。本项目用 `pid + 时间戳` 命名、跑完即删。
3. **带 `--page` 时必须给 iframe URL 拼 `#页名`**：页面壳按 `location.hash` 选页
   （`content\admin.js::boot` 见 hash 为空就 `show(PAGES[0])`），不拼就**永远只看到首页**。
4. **file:// 的 iframe 是 opaque origin**：必须加 `--allow-file-access-from-files`，
   否则外层脚本取不到 iframe 的 `contentDocument`，页面也不渲染（消息根本收不到）。

## 5. 它在本轮的价值（事实）

- 改一次 CSS → **几秒**出一张图，**不用开 Zotero**（Zotero 那侧要侧载 + 重启，一轮几分钟起）。
- **当场抓到两个真 bug**：`ctx.el` 不是函数（整页渲染失败）、切页重复取数（缓存实现缺陷）。
- 滚动/sticky 这类"要真的滚起来才看得见"的问题，也用同一回路放大：`render_scroll_preview.py`
  把 iframe 里 `#view` 的 `scrollTop` 推下去（每 100ms 重设一次，免得"量到的帧"与"画出来的帧"不是同一帧），
  再用 `--dump-dom` 把 `th` 的 `getBoundingClientRect()` 与 `getComputedStyle` 取回来对照。

## 6. 配套的两条并行工作法（同属这个范例）

1. **先冻结 API 契约再并行**：页面与引擎两边照**同一份**契约文档写，避免字段漂移。
   本项目 = `docs\ADMIN-API-W2.md`（批次 A）+ `docs\ADMIN-API-W2B.md`（批次 B），
   每份都带「实际口径」小节（契约初稿没说细、或与真实数据模型对不上的地方以那一节为准）。
   **新增方法两边都要改**：引擎加 method、宿主路由表加一行 —— 本轮靠它让多个 agent 并行不出接口错。
2. **文件不重叠 + 每个 agent 自验 + 父 agent 复核**：每个 agent **只许改自己点名的文件**
   （本轮的边界写在源码注释里，如 `14-menus.js` 的"本波只许动 23-admin / 14-menus /
   admin-pages/structure 三个文件"）；每个 agent 必须自己出图/出断言；
   **父 agent 不信报告、只信实测**（本轮多次靠真机探针、计算样式、`--dump-dom` 才定案）。
