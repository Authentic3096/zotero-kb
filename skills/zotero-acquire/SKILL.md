# 找文献 → 列候选 → 用户挑 → **Zotero 自己抓进库**

本技能覆盖**"我库里没有，去外面找并拿下来"**这条链路。
如果用户问的是"**我库里**关于…的文献"，那是 `zotero-kb` 技能的事 —— 走 `kb_search`，不要用本技能。

**五步**：搜 → 核元数据 → 列候选表 → 用户挑 → 在对话里确认并**盯着抓完**。

> **一条贯穿全程的原则（用户明确要求的使用习惯）**：
> **搜索、候选表、挑哪几篇、抓取进度、最终结果 —— 全在 DSH 对话里。**
> Zotero 那边默认**不弹任何框**（`zotero-kb.acquireConfirm` 默认关）。
> 用户的原话："查询文献都是在dsh中做，那下载列表最好也是通过dsh的对话中显示，
> 这样才是更符合使用习惯的。"
> 所以：**别把确认甩给 Zotero 的模态框，也别让对话在抓取那几十秒里一片空白。**

> **最重要的一条**：抓取用 **`kb_acquire`**（MCP 工具），它把 DOI 清单派给 Zotero 插件，
> **由 Zotero 进程自己去抓** —— 元数据走 Zotero 的翻译器，PDF 走 Zotero 自带的
> 「查找可用的 PDF」。**不要自己去写下载器**，也不要在 Python 侧下 PDF 再塞给用户。

## 为什么必须是 Zotero 去抓（这条决定了整个技能的形态）

| 理由 | 说明 |
|---|---|
| **网络身份** | 请求从 Zotero 进程发出，用的是**用户机器当下的网络环境** —— 校园网出口 IP、机构订阅、出版社会话全都天然生效。在别处下载就把这层身份丢了 |
| **不用手工拖** | 抓完**直接是一条带附件的 Zotero 条目**。用户的原话是"不要下载下来手动拉" |
| **元数据更准** | 走 Zotero 的翻译器生态（实测 "DOI Content Negotiation"），比解析搜索结果网页可靠 |
| **resolver 更全** | `addAvailableFile` 是 Zotero 自带的，自带 DOI 落地页 → 条目 url → 开放获取源 → PMC → 用户自定义 resolver 一整套 |

## 第 0 步（别跳）：先确认库里是不是已经有了

**在联网搜之前**先 `kb_search` 一次。
理由：库里已有的文献不该被当成"新发现"再抓一遍（`kb_acquire` 也会去重，但白跑一趟网络）。
如果库里已有，直接告诉用户"这篇你库里有（给 key）"，只补缺的。

## 第 1 步 · 搜

用 `web_search`。一次给 2–4 个**角度不同**的查询比一个长句子有效：

| 角度 | 例子（中性示例） |
|---|---|
| 主题 + 综述词 | `某主题 review` |
| 主题 + 年份 | `某主题 2024 2025` |
| 主题 + 方法词 | `某主题 某方法` |
| 已知的预印本库 | `某主题 arXiv` |

**不要**只搜一轮就收工。第一轮结果里的**综述文章**是最好的线索源：
用 `web_fetch` 读它的参考文献段，往往能一次拿到十几篇真正相关的文献。

## 第 2 步 · 核元数据（**必做，不要凭搜索结果写标题**）

搜索结果里的标题经常是**被截断的、带网站后缀的**，年份和作者也常缺。
写进候选表之前，用 DOI 到 **Crossref** 核一遍（免 key、开放）：

```powershell
try { [Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12 } catch {}
$ua  = "ZoteroAcquire/1.1 (DSH skill; metadata lookup)"
$q   = [uri]::EscapeDataString("某篇的标题")
$url = "https://api.crossref.org/works?rows=1&query.bibliographic=$q" +
       "&select=DOI,title,author,issued,container-title"
$r = Invoke-RestMethod -Uri $url -Headers @{ "User-Agent" = $ua } -TimeoutSec 40
$it = $r.message.items[0]
"$($it.DOI) | $($it.title -join ' ') | $($it.issued.'date-parts'[0][0])"
```

拿到 DOI 后**先自检一次**：把 Crossref 返回的标题跟你搜到的标题比一下，
对不上就说明选错条目了（`rows=1` 是"最像的一条"，不是"一定对的一条"）。

> **中文文献要注意**：中国大陆注册的 DOI 在 doi.org 上常常返回 `text/html`、
> 拿不到 CSL-JSON，Crossref 里也多半没有。所以**中文文献的 DOI 路线基本走不通** ——
> 这类文献照实列出来、DOI 栏留空或标"未核到"，并告诉用户"中文库这条得靠浏览器
> 连接器"。不要因为"核不到"就把这篇从表里删掉。

## 第 3 步 · 标一眼开放获取状态（**只是参考，不再是门槛**）

用 **Unpaywall**（免 key、开放）给候选表加一个参考信号：

```powershell
$mail = "zotero.acquire.skill@gmail.com"     # ⚠ 见坑 1，不要用 example.com
$url  = "https://api.unpaywall.org/v2/" + $doi + "?email=" + $mail
$r = Invoke-RestMethod -Uri $url -Headers @{ "User-Agent" = $ua } -TimeoutSec 40
"is_oa=$($r.is_oa) status=$($r.oa_status) pdf=$($r.best_oa_location.url_for_pdf)"
```

**这个结果现在只是给用户一个预期，不再是"能不能下"的判决**：

- `is_oa=true` → 大概率能抓到（但 `url_for_pdf` 可能为空，那也不代表没戏）。
- `is_oa=false` → **不代表抓不到**。用户要是在校园网里、或者学校订了这个刊，
  Zotero 从本机发请求就是能拿到的（等同他自己在浏览器里点下载）。
- 查不到 → 标 `⚠ 未查到`，别猜。

**宁可说不知道，也不要让用户以为一定行或一定不行。**

## 第 4 步 · 列候选表（**标题必须可点击**），让用户自己看

### 4.1 先把表列出来，**标题做成能点开的链接**

用户要能**自己点开原文看**再决定 —— 这比在表里塞摘要强：
摘要三方都常常抓不到（实测 HDSR 这类刊 OpenAlex / Crossref / S2 全没有），
而链接一定能用。

```markdown
搜到 4 篇候选（**点标题能打开原文页**）：

| # | 标题 | 作者 | 年份 | 出处 | 关键词 | 全文 |
|---|---|---|---|---|---|---|
| 1 | [某方法研究](https://doi.org/10.xxxx/yyyy) | Zhang | 2024 | 某期刊 | 甲、乙、丙 | ✅ OA |
| 2 | [某主题综述](https://doi.org/10.xxxx/zzzz) | Li | 2023 | 某期刊 | 甲、丁 | ✅ 作者版 |
| 3 | [某实证研究](https://doi.org/10.xxxx/aaaa) | Wang | 2021 | 某期刊 | 乙、戊 | 🔒 需订阅 |
| 4 | 某模拟研究 | Chen | 2022 | — | — | ⚠ 未核到 DOI |
```

**链接用 `https://doi.org/<doi>`** —— 它稳定、不会被出版社改版搞坏，
解析到哪儿就是哪儿。有正式落地页时也可以用落地页。

要不要关键词/主题，用 `kb_paper_info(dois="…")` **一次问一批**（可选）：
它给关键词、主题、OA 状态、被引数，还有摘要**（有就给，没有会明说 `abstract_source=none`）**。

- **有效就用**（帮用户决定点哪个链接）；
- **拿不到就算了**，把"关键词"那列留空 —— **不要为了填表去编一段摘要**。
- 真需要摘要又查不到时，老实说"该刊没提供摘要，点标题去原页看"。

### 4.2 然后用**可点击的勾选框**让用户挑（**不要让他回"1 3"**）

表列完，**紧接着调 `ask_user_question`**，`multi_select: true`：

```python
ask_user_question(questions=[{
  "id": "pick",
  "header": "挑文献",
  "question": "要抓哪几篇？（可多选；想先看原文就点上表里的标题，回来看完再勾）",
  "multi_select": True,
  "options": [
    {"label": "1. 某方法研究（Zhang 2024）",
     "description": "某期刊 · ✅ OA · 关键词：甲、乙、丙"},
    {"label": "2. 某主题综述（Li 2023）",
     "description": "某期刊 · ✅ 作者版（预印本）· 关键词：甲、丁"},
    ...
  ]
}])
```

**这就是"点击勾选确认"** —— 用户在 DSH 界面里勾，不用回文字。
（没有那个可交互组件的能力时，这是最接近的形态。）

**纪律**：

1. **"全文"这一列不许猜。** 只有第 3 步真查过才写 ✅；
   没查到写 `⚠ 未查到`。**宁可说不知道，也不要让用户以为一定行或一定不行。**
2. **预印本必须标出来**（"作者版/预印本，非最终版"）。用户引用时版本是要紧的。
3. **标题对不上就扔掉**（第 2 步的自检）。搜出来"看着像"但标题不符的，宁缺毋滥 ——
   实测差点把一篇讲萘暴露的论文当成可复现性文献列进去。
4. **问一轮就够**。用户勾完直接开抓，**不再有第二次确认**。

## 第 5 步 · 抓（**核心一步：勾完就抓，不再问**）

> **整件事都在对话里发生 —— 这是用户明确要求的使用习惯。**
> 他的原话："查询文献都是在dsh中做，那下载列表最好也是通过dsh的对话中显示。"
> 所以：**Zotero 那边默认不弹确认框**（`zotero-kb.acquireConfirm` 默认关），
> 确认在**第 4 步的勾选框**里就完成了。

用户勾完之后：

1. **一句话说明开始**（不要再列一遍表、更不要再问一次）：
   > 好，抓这 2 篇。抓取由 **Zotero 自己**完成，用的是你这台机器当下的网络身份；
   > 落库后还会走一遍本地模型的分类建议。

2. **派发**（**3 篇以上一定用 `wait=False`**）：

```python
kb_acquire(dois="10.xxxx/yyyy, 10.xxxx/zzzz", wait=False)
```

它会立刻返回 `job_id`，**不阻塞**。

**为什么必须拆开**：MCP 工具是一次调用阻塞到返回的。抓一篇要十几秒、
三篇就要一分钟 —— 这段时间**对话里一片空白**，用户分不清是在跑还是卡死了。

> 存到哪个分类：默认是他在 Zotero 里**当前选中**的那个分类（和浏览器连接器
> 一致）。用户如果想指定，会说"存到 XX 分类" —— 那时传 `collection_id`。
> ⚠ **不要提前报一个分类名**：那个选中项是**抓取那一刻**才读的，
> 你派发前读到的可能已经变了（真机踩过：说好落根目录、实际进了某个分类）。
> 要报就在**结果里**照实报（回报里带分类名）。

### 5.1 盯着进度，把每一句念给用户（**这一步不能省**）

拿到 `job_id` 之后，**每隔 3~6 秒**调一次：

```python
kb_acquire_progress(job_id="aq12345-1")
```

把返回的 `progress_line` 念出来，例如：

> 进行中 2/3，正在处理 10.xxxx/zzzz
> 已经好了 2 篇，其中 1 篇带上了 PDF

`finished` 变成 `true` 就停止轮询。

> **这就是用户要的"实时进度"。** 别把 `progress_line` 吞掉直接调下一次 ——
> 那样用户看到的仍然是一片空白，等于没做。

### 5.2 收尾

`finished=true` 时返回里会带：

- `format` —— **完整结果报告**（Markdown 表格），直接呈现给用户
- `keys` —— 新条目的 key 列表
- `need_reindex` —— 为真时，**再调一次** `kb_reindex(key="k1,k2")`
  让新文献立刻能被 `kb_search` 搜到（这一步也顺嘴说一句）

> **Zotero 那边还会弹一个"分类建议"的汇总框**：落库后本地模型会给这批文献
> 各推荐一个分类和标签，**一次问一批**（不是每篇弹一次）。
> 这是用户要的流程，别把它当成错误。

### 参数

| 参数 | 什么时候用 |
|---|---|
| `dois` | 用户勾中的 DOI，逗号/换行分隔。整条 `https://doi.org/...` 也认 |
| `wait=False` | **3 篇以上、或想报进度时用**。立刻返回 job_id |
| `collection_id` | 用户指定了分类时传。默认 0 = 存到他在 Zotero 里当前选中的分类 |
| `find_pdf=False` | 只要条目、不要 PDF |
| `dry_run=True` | **先试试抓不抓得到元数据，一个字节都不写库**。用户犹豫时先用这个 |
| `reindex=False` | 不想自动补抽知识库时（**只对 `wait=True` 生效**） |

### 结果怎么说

| 结果 | 怎么跟用户说 |
|---|---|
| **已入库 N 篇** | 报 N，以及其中几篇带上了 PDF。**带上条目 key** |
| **❌ 没找到可用的 PDF** | 说清"条目进去了，但没抓到全文"，并给出下面第 6 步 |
| **跳过：库里已有** | 说明去重生效了，不是失败 |
| **跳过：抓不到元数据** | 如实说，别包装成"失败"。多半是中文 DOI 或不认识这个 DOI |

> **`dry_run` 是个好习惯**：用户说"先看看有没有"的时候用它。
> 它走完整个解析、把 Zotero **真正解析出来的**标题/作者/年份摆出来，
> 但不建条目 —— 这是"抓得到"最硬的证据。
> 它也可以配 `wait=False` + 轮询。

## 第 6 步 · 没抓到 PDF 时怎么办（**按顺序试，别跳**）

**不要**一发现没 PDF 就自己去下载。按这个顺序：

1. **先看 `kb_acquire` 回报里"试过"了哪些路。** 回报里每篇会带
   `试过：doi/oa/url` 这样的标记 —— 那是 Zotero 真的试过的 resolver。
2. **让用户用浏览器连接器抓**（**这条最有效，优先推荐**）。
   在出版社页面点 Zotero 连接器图标即可。它跑在**用户的浏览器里**，
   带着用户的登录态，能过的站点比进程内抓取多。
   中文文献（知网、万方）基本只有这一条路。
3. **已知直链时，才用脚本兜底**：`tools\fetch-pdf.ps1` 下到本机
   （**它会验 `%PDF` 文件头**，这一步不能省），然后**用 `kb_attach` 挂上去** ——
   别让用户手工拖：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "<本技能目录>\tools\fetch-pdf.ps1" `
  -Url  "<PDF 直链>" `
  -Name "<首位作者姓> <年份> <短标题>"
```

```python
kb_attach(item_key="<kb_acquire 给的条目 key>", path="<脚本打印的落地路径>")
```

- `-DryRun`：只解析不落盘（实测不产生任何文件）。
- `-SelfTest`：不发网络请求，只打印解析出来的落地目录 + 自检文件名清洗。
- 落地目录固定是 `<你的下载文件夹>\zotero-acquire\`；可用环境变量
  `ZOTERO_ACQUIRE_DIR` 或 `-Dir` 改。
- 退出码就是"失败在哪一步"：`1` 参数/环境错、`2` 网络或 HTTP 失败、
  `3` 拿到的不是 PDF、`4` 文件过小。**把退出码和它打印的理由原样告诉用户**，
  不要改写成"下载失败"这种没有信息量的话。

4. **都不行** → 如实说"没找到能拿的全文"，**不要绕**。

## 第 7 步 · 确认真的进来了

`kb_acquire` 走完 5.4 的补抽之后，知识库就能搜到了。收尾时：

1. 用 `kb_search` **抽查一篇**，确认真的能搜到（不抽查等于没验证）。
2. 如果抽样显示某个新条目 `fulltext_chars = 0`，**主动告诉用户**
   "这篇条目和 PDF 都进去了，但 PDF 没有文字层（多半是扫描件），
   所以正文进不了检索"—— 不要静默地当作一篇正常文献。

## 边界（硬性，不许放宽）

先把两件**看着像、其实完全不同**的事分开：

| | 做不做 | 为什么 |
|---|---|---|
| **用用户已有的访问权限** —— 从**他自己的机器**发请求，校园网出口 IP、学校订阅的刊、他自己在浏览器里的登录态 | ✅ **可以，这正是本技能的价值** | 这等同于他自己在浏览器里点"下载"。工具只是替他点 |
| **绕过付费墙** —— 改 URL 骗计费、影子图书馆、盗用他人凭证、伪造订阅身份 | ❌ **绝不做** | 版权与合规。抓不到就说抓不到 |

这条线划在**"这个请求是不是以用户自己的合法身份发出的"**上。是 → 可以；不是 → 不行。

其余的：

| 不做 | 为什么 |
|---|---|
| **大批量无节制抓取** | 会被反爬，也违背服务条款。用户要几十篇时先请他缩到 10 篇以内 |
| **从搜索结果里直接批量抓**（用户没挑过的也抓） | 用户明确说过要"由我来决定下载哪些"。**没被挑中的一律不抓** |
| **重造 Zotero 的抓取翻译器** | Zotero 自己的翻译器生态就是干这个的，重造必输 |
| **保证"列表里的都能抓到全文"** | 取决于出版社与用户当下的访问权限。候选表里明示，让用户决定 |
| **判断"这篇文献质量高不高"** | 只能报客观信号（是否综述、是否预印本）。**不要把"我推荐"包装成"这篇好"** |

## 踩过的坑（都实测过，照做即可）

1. **Unpaywall 拒绝 `example.com` 这类占位邮箱**，返回 `422`（响应体是空的，
   光看状态码查不出原因）。换一个正常形状的邮箱就 200。
2. **OpenAlex 的 JSON 在 Windows PowerShell 5.1 里 `ConvertFrom-Json` 会报
   `duplicated keys 'The' and 'the'`**（5.1 的 JSON 解析器不区分大小写键）。
   所以本技能的 OA 查询用 **Unpaywall**，不要改用 OpenAlex 再自己解析。
3. **不要只看 HTTP 状态码**。`200` + HTML 验证页是常态。**永远校验文件头。**
4. **403 不等于没有免费版**。MDPI、IEEE、ScienceDirect 等对脚本访问有反爬
   （本机实测 MDPI 文章页 403、ScienceDirect `/pdfft` 403）。这时走第 6 步，
   而不是反复重试同一个域名 —— 重试只会更快被封。
5. **标题里带 `?` `:` `/` 是常态**，不能直接当文件名。用 `-Name` 让脚本清洗。
6. **别把"抓到了"报成"能搜了"**。条目 ≠ 有 PDF ≠ 知识库能搜到。
   `kb_acquire` 会顺带补抽，但**你仍然要抽查一次**。
7. **改了插件代码，运行中的 Zotero 不会自动用上。** 尤其当插件是**真 xpi** 装的
   （`extensions\zotero-kb@authentic3096.github.io.xpi`）：profile 里那份会一直是旧的，
   表现为"我明明改了、怎么还报同样的错"。**验证前先确认版本**：
   `python tools\check_acquire.py` 的第 3 段会报「插件版本 X.Y.Z」。
   没重启/没重装时 `kb_acquire` 会明确报"插件是 X，要 Y 以上" ——
   看到这句就去重启或重装，**不是**重装 Python 环境。
8. **"没抓到 PDF"有两种表现，别混**。Zotero 的 `addFileFromURLs` 一条路都没走通时
   —— 有时对 `false` 做对象解构**抛异常**，有时**直接返回假值**（既不抛也不给
   `noFileFound`）。所以判据要写成"`error` 有值 = 真出错 / `tried` 里有东西 =
   确实试过了但没找到"。**只看 `noFileFound` 会把"试过没找到"误报成"未尝试"**
   （实测踩过：同一行同时出现"—（未尝试）"和"试过：doi/url/oa/oa"，自相矛盾）。
9. **中文文献的 DOI 路线基本走不通**（见第 2 步）。别在这上面耗时间，
   直接告诉用户用浏览器连接器。
10. **"Zotero 没开"和"插件没在轮询"是两回事，修法也不同**。插件状态文件**每 30 秒
    才写一次**，Zotero 刚关掉时它看着还是新的 —— 单看它会得出错误结论
    （实测：Zotero 关了 4 分钟，前置检查仍放行，任务干等 30 秒才报"插件没在轮询"）。
    要判 Zotero 本身在不在，**打它的连接器端口 `http://127.0.0.1:23119/connector/ping`**
    —— 任何 HTTP 响应（哪怕 404）都说明进程活着，连不上才是没开。
11. **ScienceDirect / 知网这类站点的 PDF，进程内抓取拿不到是常态**
    （需要 cookie/token）。实测一篇 diamond OA 的 ScienceDirect 论文，
    Zotero 把 `doi → url → oa → oa` 四条路都试了仍然没有。
    **这不是调参能解决的，直接让用户上浏览器连接器。**

## 一句话总结

**搜要搜够（多角度 + 读综述的参考文献），表要列准（DOI 核过、OA 状态查过、预印本标出来），
挑要让用户挑（他只说哪几篇，没说的不抓），抓要交给 Zotero（`kb_acquire`，用它自己的身份
和自己的 resolver），抓不到就按顺序退（连接器 → 脚本 + `kb_attach` → 如实说没有），
收尾要抽查（条目 ≠ 有 PDF ≠ 能搜到，三件事分开说）。**
